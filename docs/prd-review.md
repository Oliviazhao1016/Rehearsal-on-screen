## 初步审核发现

| 优先级 | 缺口或冲突 | 对用户体验的影响 | 建议与待决策项 |
| --- | --- | --- | --- |
| P0 | 首版主用户、核心任务和完成标准未出现在可见正文 | 难以判断功能是否必需 | 先确认首版最重要的使用结果 |
| P0 | 用户要求路线配合 Cue；草稿把 Cue 绑定放在未来 | 可画路线但可能无法完成预期排演 | 明确是静态讲解、单场动态预演，还是跨场换景 |
| P0 | 有移动时长，没有明确启动条件 | 不知道何时移动及如何与其他对象同步 | 确定时间触发、手动 GO 或其他方式；先选一种主方式 |
| P0 | Scene 内创建对象，但用户提到幕间衔接 | 跨场景的对象身份与状态可能中断 | 定义场与幕的关系、对象复用和前后场状态 |
| P1 | Actor 的四个已认可属性不可见，当前草稿仅明确三项创建属性 | 字段定义不一致 | 后续补齐原始定义或逐项确认，不自行补第四项 |
| P1 | Position、Stage Mark、对象当前位置的区别不清楚 | 拖动可能误改其他时刻或其他演员的站位 | 用用户操作示例说明各概念及修改作用范围 |
| P1 | 道具只定义起终点，未明确路线形状和场外区域 | 无法判断是否能表达侧台上场、绕行和退场 | 明确场外摆放、直线或折线路线、显示规则 |
| P1 | 未说明播放、暂停、重播和拖动时间位置的结果 | 用户无法验证完整走位或重复排练 | 为选定的首版任务补齐预演流程和验收示例 |
| P1 | 删除与修改对象的关联影响未定义 | 可能破坏已编排路线和 Cue | 规定提示、关联处理、撤销或恢复行为 |
| P1 | 保存、重开、分享与交付方式未出现 | 工作成果是否可复用不明确 | 最少确认保存与重开；分享按使用场景决定 |
| P2 | 道具类型与显示图形可能重叠 | 创建表单可能增加无效选择 | 确认类型是否有实际业务行为，否则先保留名称与图形 |

## 访谈顺序

首版核心结果 → 使用者与实际排演案例 → 最小完整流程 → 触发与时间规则 → 站位和路线 → 跨场状态（如在范围内）→ 编辑与异常行为 → 保存交付 → 验收标准。

每轮更新已确认决策、未决问题和范围变化。推荐方案在用户回答前不视为已确认需求。

## 当前问题 Q1：首版核心结果

首版用户完成一次操作后，最重要的成果是什么？

- A（推荐）：完成一个场景的动态预演，能够看到演员走位、道具移动按设定顺序或时间发生。推荐理由：可验证空间、动作与触发的完整流程，同时控制首版范围。具体触发方式下一轮决定。
- B：完成跨场景换景预演，验证上一场结束到下一场开始的道具进退场和 Cue 配合。如果用户当前最痛的是幕间衔接，应选此项。
- C：完成静态站位图和路线说明，用于与演员沟通，暂不要求播放。

用户答案（2026-09-22）：MVP 注重 A，即单场景动态预演。已写入主 PRD；具体动作触发方式仍待确认。
